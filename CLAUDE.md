## Design direction
- Style reference: fin.ai. The element library is `docs/design-library/fin-ai.md`; refer to elements by ID (e.g. `C-07`). §9 maps elements to our sections. Use Fin's patterns, never Fin's copy, logos or 3D assets.
- Light theme only. No dark mode (the dark section 05 band and the dark `/contact` page are deliberate design choices, not a theme).
- Minimal, modern, "AI-native" feel. Generous whitespace, thin borders.
- No scroll-triggered animations, parallax, marquees, carousels or auto-playing motion. Small hover states are fine. **Exceptions (owner requests), all respecting reduced motion:** the section 05 loop diagram; the RAG squares in 1.2 blinking like status LEDs, red → amber → green a third of a cycle apart (`.rag-blink` in globals.css, 1.8s, opacity only; owner request 12 Oct 2026); the "What we deliver" stat numbers counting up from zero once on scroll (`count-up.tsx`: 1.6s ease-out, digits only, "24/7" stays still, final value reserved so nothing shifts, trigger at 12% above viewport bottom); the section numbers rolling in once on scroll (`rolling-number.tsx`, copied from fin.ai: masked digits rise 1em and fade in, 1s/0.8s, 80ms stagger, trigger at 12% above viewport bottom); and the liquid ribbon (`liquid-ribbon.tsx` + `src/lib/air-ribbon-scene.ts`): the hero and closing render is the static WebP first, then a live three.js copy of the same scene fades in and ripples slowly (12s seamless loop, frame 0 = the WebP). three.js loads only when a ribbon is near the viewport; it runs at 30fps only while on screen, pauses in background tabs, caps canvas resolution at 2× / 2.4 megapixels, and falls back to the static image for reduced motion, no WebGL2 or a lost GPU context. If the WebP is ever re-rendered, update the constants at the top of `air-ribbon-scene.ts` to match (colours, rotation, 3000px frame and the trim box).
- Keep scrolling short. Few sections, nothing padded out.
- Mobile-first and accessible: semantic headings, visible RAG labels, AA contrast.
